# dev-instruction

Claude Code 프로젝트에 공통 적용하는 **범용 개발 지침 템플릿** 저장소.

## 파일

| 파일 | 내용 |
|---|---|
| `CLAUDE.md` | 행동 원칙(사고·단순함·외과적 변경·목표 기반 실행), 검증 게이트, 역할·모델 위임, 근거 등급, 응답 규칙 + 프로젝트별 채움 섹션 |

## 사용법

1. `CLAUDE.md`를 대상 프로젝트 루트로 복사
2. 하단 「프로젝트 인덱스」의 `[ ]` 항목을 채우고 해당 없는 행은 삭제
3. 페르소나 로스터가 있으면 「에이전트 등록·라우팅」을 `.claude/agents/`의 실제 이름으로
   채움. 없으면 §6 「부트스트랩」으로 시작(아래 적용 사례)
4. 규칙이 바뀌면 지침(한 줄)과 근거 문서(본문)를 함께 수정

`CLAUDE.md`는 이 파일과 `.claude/agents/`만으로 성립하며 외부 스킬·저장소에 의존하지 않는다.

## 적용 사례 — 새 프로젝트에서 로스터까지

| 단계 | 하는 일 | 상태 |
|---|---|---|
| 1. 설치 | `CLAUDE.md` 복사, 프로젝트 인덱스(포트·검증 도구·파일 맵·공유 환경) 채움, 상단 적용 방법 블록 삭제 | 로스터 없음 |
| 2. 부트스트랩 | 메인이 직접 구현. 기계 검증(훅)·실무자 게이트 기준은 동일하게 적용. 서브에이전트는 즉석 파견문(6항)으로 2~3회 사용 | 로스터 없음 |
| 3. 반복 감지 | 파견문마다 똑같이 써넣는 지시(계층 규칙·포트·검증 관례·금지사항)가 보임 — 이것이 페르소나의 재료 | 신호 |
| 4. 로스터 구축 | §6 「로스터」 절차: 반복 추출 → `.claude/agents/*.md` 작성 → 인덱스 「에이전트 등록·라우팅」 채움 | 로스터 성립 |
| 5. 첫 실전 | 실제 작업 1건을 새 라우팅으로 실행. 구현↔검증 분리가 결함을 잡는지, 파견문이 짧아졌는지 확인. 이후 메인은 코드 직접 수정 금지 | 운영 |
| 6. 성장 | 실패 사례마다 해당 페르소나 파일에 날짜와 함께 교정 추가 | 운영 |

4단계는 손으로 해도 되고, 같은 절차를 자동화한 별도 스킬
[persona-governance](https://github.com/boonblade/persona-governance)(`SKILL.md`를
`~/.claude/skills/persona-governance/`에 복사 후 대상 프로젝트에서 `/persona-governance`)를
써도 된다. 스킬은 선택 사항이며 `CLAUDE.md` 본문은 스킬 유무와 무관하게 동작한다.

## 원칙

- 지침에는 규칙만 싣고 근거·사례·상세는 문서로 링크
- 이력·진행·대기 목록은 지침에 두지 않음(갱신되지 않으면 더미가 됨)
- 프로젝트 고유 값(포트·환경 식별자·파일 맵)은 템플릿 본문이 아니라 채움 섹션에만
- 본문은 스택 무관 원칙, 구체성은 채움 섹션의 **기본값**(웹 앱 기준)으로 공급. 빈 칸 `[ ]`는
  추측으로 메우지 않는다 — 범용화가 추측을 낳지 않도록 세 겹(원칙·기본값·빈 칸 금지)
